# 0006 — Cloudflare Workers target

Status: accepted (2026-10-31)

## Decision

- `apps/server-cloudflare/src/worker.ts` turns the shared HTTP app into a fetch handler with `HttpRouter.toWebHandler`, built once per isolate from the bindings, and passes a per-request `BackgroundTasks` backed by `ctx.waitUntil` (see 0005).
- Persistence: D1 (`DatabaseD1.layer(env.DB)`) for all repositories; rate limiting on KV (`RATE_LIMITS`, approximate under bursts) with automatic fallback to the D1 limiter when the binding is absent.
- Configuration: string vars and secrets are read through `ConfigProvider.fromEnvRecord(env)`, so the same `Config` definitions serve Node (`process.env`) and Workers.
- `wrangler.jsonc` contains placeholder ids only (`database_id` `00000000-0000-0000-0000-000000000000`); no tooling in this repo creates or touches remote resources. Local development uses `wrangler dev --local` and `wrangler d1 migrations apply DB --local`.
- D1 migrations are generated by drizzle-kit and copied into wrangler's flat layout by `scripts/sync-migrations.ts`; a test fails when they drift.
- `nodejs_compat` is enabled for library compatibility; the Worker bundle never imports `@dadalink/db/node`.
- Verified locally: FTS5 virtual table and triggers apply on local D1; `/health`, content queries and the assistant (KV quota) respond under `wrangler dev --local`.
